## Why this split
- **`data/repositories`** is the seam the spec's §34/§35 require: every module reads/writes through
  a repository interface, never raw fetch calls scattered through components. Today's repositories
  can be implemented against on-device storage; the production implementation talks to
  `server/routes/*` over the contracts in `API_CONTRACTS.md`. No UI rewrite when that swap happens.
- **`data/sync`** sits underneath the repositories, not beside them — every repository write still
  goes through the same local save it always did; the sync layer just also enqueues that write for
  the server. See `docs/SYNC_PROTOCOL.md` for the full design (Phase 1: whole-collection snapshot
  sync with reject-on-conflict; Phase 2: per-record operation log once Phase 1 is proven in daily use).
- **`server/services`** hold the AI/OCR/voice/sync logic so it's testable and swappable independent of
  which model, OCR provider, or sync strategy is wired up.
- Role/permission checks live in `server/routes/*` (§43: enforced in the service layer, not just hidden UI).

## Build path to a real device
This sandbox has no network access, so it cannot run `npm install`, `npx cap add android`, or compile
an APK locally. Two real paths exist now:

**CI (automated):** push to `main` and `.github/workflows/android-apk.yml` runs the full chain on
GitHub's runners (which do have network) and uploads a debug APK as a workflow artifact. See the
root `README.md` for the exact push/trigger steps.

**Locally, on your own machine:**
```
npm install
npm run build             # packages preview/index.html into dist/ — see scripts/build-web.mjs
npx cap add android       # generates the full android/ Gradle project from capacitor.config.ts
npx cap sync android
npx cap open android      # opens Android Studio
```
`android/` is intentionally `.gitignore`'d — it's fully derived from `capacitor.config.ts` + `dist/`,
so both CI and local builds regenerate it fresh via `cap add android` rather than trusting a possibly
stale committed copy.
